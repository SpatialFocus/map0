Data sources

WFS

Live features straight from an OGC Web Feature Service — an endpoint and a type name in the config, and map0 handles the GetFeature requests, the GeoJSON negotiation and the paging. Rendered exactly like a GeoJSON layer.

Try it: open the network tab and reload — the 3,214 trees of Alsergrund arrive in pages of 1,000 (count/startIndex), fetched until the server's reported total is reached. The fountains load city-wide in one page and cluster; click any feature for its live attributes.

Configuration

The GeoJSON demo used to recommend hand-building a GetFeature URL with outputFormat=json&srsName=EPSG:4326. The wfs type is that trick, formalized: url + typeNames replace the URL assembly, and everything after the fetch — styling, clustering, popups, hover — is the geojson pipeline. 


      


      

        
What this demo shows

        
    
          
  • A wfs layer needs url and typeNames — version, output format and CRS have working defaults
    • 
          
  • WFS 2.0 paging: pages of pageSize (default 5000) until the server's total or the limit (default 10000) is reached
    • 
          
  • A server that silently caps a request below the asked-for count is continued from where its answer actually ended
    • 
          
  • params passes vendor parameters — here cql_filter moves the district filter to the server
    • 
          
  • A WFS reports errors as XML with HTTP 200 — map0 unwraps the exception text into the layer's error state
    • 
          
  • Styling, clustering, popups, hover, promoteId — exactly the geojson options
    • 
        

        

          The service must speak GeoJSON and CORS.
          map0 requests application/json in WGS84 — GeoServer and deegree take that
          as-is, MapServer wants "outputFormat": "geojson". A server offering neither
          GeoJSON nor CORS headers cannot be read by a browser client. version: "1.1.0"
          falls back to a single maxFeatures request (paging is WFS 2.0).
        

      


      

        
When to reach for WFS

        

          When the data changes and the map should follow: every load asks the service, so edits in
          the source database show up on the next reload — no re-publishing a file. Server-side
          filtering via cql_filter keeps the transfer to the features a map actually
          needs. The flip side is per-request latency and untiled transfer sizes: for a static
          snapshot the same data travels far cheaper as
          GeoParquet, and a feature type beyond the
          limit ceiling belongs in vector tiles (PMTiles). A service that also offers
          OGC API Features is better read through that
          interface. The
          limit default of 10,000 is deliberate — it keeps an accidental
          typeNames against a country-sized table from pulling millions of features
          into the page.
