Configuration

Validate a config

A broken config never leaves a blank map — it is validated before anything renders, and the errors carry the JSON path that caused them. This page runs that same validator on whatever you paste, and lists every other place a config gets checked on its way from editor to page.

Paste a config

This is map0's own validateConfig, compiled into this page exactly as it is compiled into the viewer — not a lookalike. Errors block the map; warnings (an unknown key is the classic) never do, so a config written for a newer map0 still opens.

One difference to the viewer: the viewer resolves extends before validating, so a child config may leave basemaps to its base — here the document is checked exactly as pasted.

Every place a config is checked

In your editor, as you type

The config format has a published JSON Schema. A $schema line is all it takes — VS Code, JetBrains and Monaco embedded in a CMS then offer autocomplete, documentation on hover and squiggles under typos while you write: 

          {
            "$schema": "https://map0.net/schema/v1.json",
            "version": 1,
            "basemaps": [{ "type": "style", "url": "…" }]
          }

In CI, before it ships

The same schema works with any JSON Schema tool — a check in a pipeline or a CMS save hook costs one command: 

          npx ajv-cli validate -s node_modules/map0-viewer/schema/v1.json -d my-map.map0.json

check-jsonschema does the same on the Python side. The schema checks structure — keys, types, ranges, required fields — which is exactly what an editor or a pipeline should catch.

In your own code

The validator on this page is part of the npm package, reachable through the SSR-safe entry — no DOM required, so a Node backend can refuse to save a broken map: 

          import { validateConfig } from "map0-viewer/ssr";

          const { valid, errors, warnings } = validateConfig(config);
          // errors: [{ path: "$.layers[0].url", message: 'a "wms" layer needs a "url"' }]

In the viewer, always

Whatever slipped through still cannot produce a blank map: the viewer validates before it renders and shows the errors in place. This layer also enforces what a JSON Schema cannot express — the https-only URL policy, id uniqueness across basemaps and layers, and cross-field rules like a color ramp's min below its max. 

          $.basemaps          at least one basemap is required, e.g. { "type": "style", "url": "…" }
          $.layers[2].url     a "wms" layer needs a "url"
          $.layers[2].layers  a "wms" layer needs "layers" (WMS LAYERS parameter)

The schema, published

One file, three URLs — pick by how you want it to move:

  • https://map0.net/schema/v1.json — follows the latest release; the URL to put in a config's $schema line
  • https://cdn.jsdelivr.net/npm/map0-viewer@0.2.0/schema/v1.json — pinned to one release, from the npm tarball
  • node_modules/map0-viewer/schema/v1.json — offline, next to the bundle you installed

The file is named after the config format version ("version": 1), not the package version. It is hand-written — the descriptions are the editor documentation — and a test locks its key sets and enums to the runtime validator, so the two cannot drift apart.
