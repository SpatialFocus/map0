Data sources

WMTS

Pre-rendered tiles, configured the way an SDI thinks about them: a capabilities URL and a layer identifier. Everything else is read from the service.

Try it: two WMTS layers from basemap.at over a grey basemap — terrain shading at 70 % opacity and a label overlay on top.

What this demo shows

  • No hand-written tile template — url points at WMTSCapabilities.xml
  • map0 picks the first WebMercator-compatible tile matrix set and warns when a layer offers none
  • REST and KVP services both work; matrix identifiers like EPSG:900913:7 are mapped onto {z}
  • Zoom range, default style, bounds and legend come from the capabilities document

Capabilities are parsed in the browser with @camptocamp/ogc-client, in a worker, so a 30 000-line XML document does not block the map.

Field note: dead mirrors basemap.at advertises five tile hosts in its capabilities, four of which no longer resolve in DNS. map0 probes one real tile per candidate host and uses the first that answers — a map that silently stays empty is the worst possible failure mode.
