Configuration

Minimal config

The promise from the specification: a version and one basemap must already produce a usable map. Everything else is a default you can override, never boilerplate you must write.

Note: no view, no controls, no theme configured — yet you get zoom, compass, fullscreen, geolocation, globe, scale bar, attribution, coordinate readout, print and a light/dark theme that follows the operating system.

The whole thing

The config above is embedded in the page itself — no separate file, no build step:

          <script type="module" src="/map0.js"></script>

          <map0-viewer style="height:520px">
            <script type="application/json">
              {
                "version": 1,
                "basemaps": [
                  {
                    "type": "style",
                    "url": "https://mapsneu.wien.gv.at/basemapv/bmapv/3857/resources/styles/root.json"
                  }
                ]
              }
            </script>
          </map0-viewer>

Three ways to hand over a config, in this order of precedence:

  • A config property set from JavaScript (for SPAs and wrappers)
  • A config-src attribute pointing at a JSON file
  • An inline <script type="application/json"> child, as above — the CMS-friendly one

When the config is wrong

A broken config never leaves a blank map. It is validated before anything renders, and the errors are shown in place with the JSON path that caused them — so an editor can fix it without opening a developer console: 

          $.basemaps          at least one basemap is required, e.g. { "type": "style", "url": "…" }
          $.layers[2].url     a "wms" layer needs a "url"
          $.layers[2].layers  a "wms" layer needs "layers" (WMS LAYERS parameter)
