Playground

The config on the left, the map it produces on the right. Start from the example or bring a demo over, edit, apply — mistakes are caught below the editor by the same validator that guards every embedded map.

What the validator cannot see: a config can be valid and still point at services this browser may not read (CORS) — the affected layer then reports its error on the map. http:// URLs are rejected outright: map0 loads over https only.

How configs get here

  • Every demo carries an “Open in the playground” link under its map — the config comes along.
  • ?config=/configs/wms.map0.json loads any config file of this site into the editor.
  • The map only reloads when you apply a valid config — while you type, the last working map stays and blurs once the editor has moved ahead of it.

Validation here is the first line, not the whole story — where else a config is checked on its way from editor to page is on Validate a config.
